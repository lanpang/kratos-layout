# Feature Requests

用户、外部系统、运维或开发过程中提出但还未决定如何处理的需求入口。

和其他文档的分工：

- `feature-requests.md`：还没决定怎么办的需求。
- `roadmap.md`：已经决定做的计划和 backlog。
- `bugs.md`：已经发生的错误或回归。
- `docs/adr/`：长期架构取舍。
- `non-goals.md`：明确拒绝、不再反复讨论的方向。

## 条目格式

- **日期**：YYYY-MM-DD，使用绝对日期。
- **来源**：user / ops / dev / external / integration。
- **原话/诉求**：尽量保留原始表达。
- **状态**：pending / researching / planned / in-progress / shipped / rejected。
- **去向**：roadmap / API / ADR / bug / smoke / runbook / commit / rejected reason。

新 request 先进 `Open`。分流完成后挪到 `Resolved`，最新在上。
